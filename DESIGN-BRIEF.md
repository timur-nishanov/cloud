# Дизайн-бриф: полиш прототипа «Собери свой идеальный бандл»

Тач-интерактив Yandex Cloud для стенда на конференции Scale 2026.
Гость решает бизнес-задачу, собирая связку (бандл) из сервисов платформы
данных. Концепт айдентики: **сервис = деталь конструктора, бандл =
собранный механизм, правильная сборка = схема заработала → загорается
лампа включённости #BFFF00**.

Прототип уже собран и работает. Твоя задача — **причесать визуал, не
пересобирая ничего**. Это полиш-проход, не редизайн.

---

## 1. Что НЕ трогать

- **Механику и логику** (`app.js`): навигация, drag&drop, тап-постановка,
  проверка сборки, сигнал, таймер, вердикты — работают, не менять.
- **Структуру экранов и порядок флоу**: attract → выбор режима → выбор
  задачи → сборка / готовые бандлы → результат.
- **Тексты и данные** (`const DATA` в app.js) — это контент-заглушки
  заказчика, их заменят после ревью. Не редактировать и не «улучшать».
- **Стек**: статика без зависимостей — `index.html` + `style.css` +
  `app.js`. Никаких фреймворков, сборщиков, CDN, внешних запросов.
  Должно открываться двойным кликом по index.html (file://) и деплоиться
  на Vercel как есть.
- **Сцену**: макет 1920×1080, масштабируется JS-ом через transform scale
  (#stage). Всё позиционируется в координатах 1920×1080.
- **TODO-комментарии в коде** — это открытые вопросы к заказчику,
  не удалять.
- **Ассеты**: использовать только то, что лежит в репо (см. п. 3).
  Не рисовать свои иконки/иллюстрации, не подключать шрифты извне.

## 2. Железные правила бренда (нарушение = брак)

Полные правила — в `CLAUDE.md` в корне репо. Ключевое:

**Палитра (точные значения, не менять):**
- Основная: синий `#2A9FFF`, чёрный `#000000`, белый `#FFFFFF`,
  бежевый `#FCC67F` (акцент).
- Расширенная — ТОЛЬКО мелкие детали (винты, провода, шашки, статусы):
  серо-голубой `#B0BDD9`, светлый `#E7EBF4`, розовый `#FFB3ED`,
  фиолетовый `#B43ACE`, зелёный `#A5F898`.
- `#BFFF00` — сигнальный лайм. Применяется ТОЛЬКО как состояние успеха:
  лампа включённости + подсветка цепочки в момент, когда схема заработала
  (провода, терминалы, обводка деталей — класс `.live`, см. п. 4.5).
  Больше нигде и ни в каком виде: ни в тексте, ни в декоре, ни в фонах.
- Пропорция на экране: синий/чёрный/белый ~85%, бежевый ~10%,
  расширенная ~5%.

**Запрещено наглухо:** градиенты, тени, glow, blur, полупрозрачности,
скругления «для красоты», эмодзи, иконки не из репо, Google Fonts / CDN.
Всё строго флэт.

**Типографика:**
- Заголовки: YS Display Black (weight 900), плотный интерлиньяж 0.98–1.05.
- Наборный текст: YS Text Regular.
- Маркировки на графике (роли слотов, теги, подписи): CoFo Sans Semi-Mono,
  капсом, трекинг сдержанный (.03–.05em, не разгонять).
- Шрифты уже подключены из `fonts/` через @font-face — не менять.

**Моушн:** плавный, единый ease `cubic-bezier(.22,.61,.36,1)` (переменная
`--e`). Без steps/«лоу-фпс», без fade/opacity-переходов, без морфинга,
без bounce и произвольных вращений. Появление — вертикальный выезд
(.cut), стыковка — snap 1.045→1, сигнал — rAF по узлам цепочки,
вердикт — пословный выезд из-под маски. Это уже реализовано — сохранить
характер, можно доводить тайминги.

**Визуальный язык «конструктор»:** всё интерактивное — детали: флэт-плиты
с одним крупным скруглением/срезом угла, винты-отверстия, слоты с
пунктиром, связи — провода с терминалами-креплениями (чёрный круг +
синяя точка), шашки как декор-мелочь. Референс сборки —
`constructor-example/`. (Розовые капсулы-соединители из брендбука сейчас
не используются — см. п. 2.1.)

## 2.1. Решения заказчика — не переигрывать

Это уже обсуждено и утверждено, менять нельзя:

- **Композиция строго спокойная.** Никакой «пляски»: карточки в ряд без
  вертикальных сдвигов, элементы не разбрасываются по экрану случайно.
  Всё выравнивается по сетке. Заказчик отдельно просил аккуратность
  вместо динамики.
- **Заголовок attract — плиты по двум колонкам** (x=170 / x=630, ровный
  шаг строк). Капсулы-соединители между плитами убраны по просьбе
  заказчика; в коде оставлен TODO — вернуть только после согласования.
- **Логотип и CTA на attract — по центру.** CTA крупный (тач, не «кнопка
  сайта»). У CTA не использовать transform для центрирования — он
  конфликтует с анимацией появления (уже наступали на это).
- **Кнопка «Назад» — компактная и без стрелки-глифа.** Она не должна
  конкурировать с основными действиями.
- **Успех подсвечивает всю цепочку**, а не только лампу: провода,
  терминалы и обводка деталей загораются лаймом (класс `.live` на
  контейнере цепочки). Работает и на экране сборки, и на результате.
- **Подложка-паттерн всегда снизу.** `.grid-bg` лежит на `z-index:-1`,
  поэтому фон белым красится на `#stage`, а НЕ на `.inner`. Если вернуть
  фон на `.inner` — подложка исчезнет. Не менять эту схему слоёв.
- **Подписи-служебки убраны** («Прототип», «контент-заглушки»,
  «Платформа данных», «Scale 2026 · Интерактив») — не возвращать.

## 4. Где именно нужен полиш (по приоритету)

1. **Оптические отступы и сетка везде.** Пройтись по всем экранам:
   выравнивание блоков, равные поля, вертикальные ритмы. Сейчас местами
   «на глаз».
2. **Хиро (attract).** Довести геометрию плит заголовка: оптические
   зазоры между строками и колонками, кегли слов относительно друг друга,
   вертикальная связка заголовок → подпись → CTA. Паттерн по краям не
   должен спорить с лентой тегов внизу.
3. **Карточки задач (экран «Выбери бизнес-задачу»).** Единый визуальный
   вес тематических иконок (они разной ширины и плотности), выравнивание
   типа / заголовка / описания по базовым линиям между карточками.
   Ряд — ровный, без вертикальных сдвигов.
4. **Карточки режимов.** Композиция иллюстраций-деталей в правом нижнем
   углу (сейчас корректно, но можно интереснее — например, по мотивам
   `constructor-example/`), баланс левой текстовой колонки.
5. **Экран сборки.** Вертикальный баланс: задача → цепочка → палитра →
   кнопки. Роли под слотами, связи-провода, лампа — выровнять оптически.
   Палитра из 13 плиток: ритм двух рядов.
6. **Готовые бандлы.** Схемы связок внутри карточек A/B/C: интервалы
   деталь-провод-деталь, буква-маркер, состояние selected (инверсия
   в синий) — проверить контрасты.
7. **Результат.** «В точку!» + цепочка + лампа + монетный коллаут:
   вертикальная композиция, размер лампы относительно чипов, ширина и
   внутренние отступы бежевой плашки (сейчас `width:fit-content`), её
   выравнивание по центру цепочки. Проверить, как читается лайм-подсветка
   цепочки рядом с бежевой плашкой.
8. **Вердикт-панель** (ошибка сборки): высота, отступы, блок «Правильная
   связка».
9. **Состояния кнопок**: disabled сейчас серый из расширенной палитры
   (полупрозрачность запрещена) — можно предложить решение лучше,
   оставаясь в палитре.

## 5. Контекст показа

- Целевая поверхность: тач-стойка 55", 4K (сцена 1920×1080 → ×2).
  Тач-цели не уменьшать: плитки ≥88px, кнопки ≥72px высотой.
- Ближайшее демо: браузер на десктопе, управление мышью, деплой Vercel.
- Выставка = яркий свет: белые фоны, обводки 2–3px, высокий контраст,
  никаких серых полутонов в тексте.
- Hover-состояний нет (тач): только active/pressed.
- `?attract=blue` — синяя тема attract-экрана для стойки (маяк через
  зал). Проверить обе темы. `?kiosk` скрывает курсор — не трогать.

## 6. Критерии приёмки

- Оба флоу проходятся мышкой на 1920×1080 без наездов и обрезок:
  сборка (успех / ошибка → «Исправить» / ошибка → «Показать связку» /
  таймаут) и готовые бандлы (В точку / Сойдёт / Мимо / таймаут).
- Палитра — только значения из п. 2, `#BFFF00` ровно один раз на экран.
- Ни одного градиента/тени/полупрозрачности/fade в файлах.
- Подложка-паттерн не перекрывает контент ни на одном экране
  (проверить плашку монеты на результате — на ней это ловилось).
- Лайм появляется только в момент успеха, на остальных экранах его нет.
- Шапки и кнопка «Назад» остаются абсолютно позиционированными
  (не превращать в поток — ломает центровку логотипа).
- Шрифты — только три подключённых начертания.
- Работает с file:// (без fetch и внешних URL) и на окне произвольного
  размера (letterbox чёрный).
- TODO-комментарии на месте.
- Механика не изменилась (диффы в app.js — только вёрстка/координаты
  композиций: HERO_WORDS, HERO_JOINTS, buildModeArt и т.п.).
